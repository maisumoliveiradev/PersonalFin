# ADR-0010 --- Financial Space Ownership and Access Model (v0.1)

## Status

Superseded by ADR-0015 (2026-09-25, SDD-034). Originally accepted
(2026-09-23, SDD-003).

## Context

SDD-003 introduces Financial Spaces. A space has exactly one Owner
(DR-006, FR-003), and the creator becomes the Owner. Shared spaces,
invitations, granular permissions, and ownership transfer arrive in
v0.6.0 (Collaboration). Every later financial record is scoped to a
space (DR-005), so the access check introduced now protects all future
data.

## Decision

-   Ownership is the column `financial_space.owner_user_id` (`NOT NULL`,
    foreign key to `user`). "Exactly one Owner" is therefore enforced
    by the schema.
-   In v0.1 a user can access a space only if they own it. All reads go
    through repository methods that filter by the requesting user
    (`listAccessibleTo`, `findAccessibleTo`), so there is no unscoped
    lookup of a space by ID.
-   Space-scoped endpoints resolve the space with
    `requireAccessibleSpace(userId, spaceId)`. A space that does not
    exist, is not accessible, or has a malformed ID returns
    `404 FINANCIAL_SPACE_NOT_FOUND`. The same answer in every case
    avoids revealing that another user's space exists.
-   Lifecycle state is stored (`lifecycle_state`), and the check
    constraint allows only `active` until the archive/deletion workflow
    exists.
-   Space IDs are UUIDs generated by the API. The API can later accept
    client-generated IDs for offline creation without breaking
    compatibility.

## Alternatives Considered

1.  **Membership table with an `owner` role now.** It prepares for
    sharing, but adds a second source of truth for ownership and code
    paths no feature uses yet. It will be introduced by the
    Collaboration SDD, which will supersede this ADR.
2.  **403 for inaccessible spaces.** It reveals that the ID exists.

## Consequences

-   When collaboration arrives, access checks change inside the
    repository/access function, not in every route.
-   Deleting a user who owns spaces is blocked (`ON DELETE RESTRICT`)
    until account deletion (FR-015) defines the process.
